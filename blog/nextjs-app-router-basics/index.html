Getting Started with the Next.js App Router

The App Router is the default in modern Next.js projects. Here's how file-based routing, layouts, and server components fit together.

If you've used the Pages Router (pages/index.js), the App Router can feel like a parallel universe. The mental model is different — but once it clicks, you'll appreciate nested layouts, streaming, and server-first rendering out of the box.

The app/ Directory

Every folder inside app/ defines a route segment. A file named page.tsx makes that segment publicly accessible. Special files like layout.tsx, loading.tsx, and error.tsx colocate concerns per route. 

app/
  layout.tsx      # Root layout (html, body, nav)
  page.tsx        # /
  blog/
    page.tsx      # /blog
    [slug]/
      page.tsx    # /blog/:slug

Layouts Persist Across Navigation

Unlike the Pages Router where layouts required custom _app.js hacks, App Router layouts wrap child routes and preserve state during client-side transitions. Your sidebar stays mounted while content swaps — fewer loading flashes, better UX.

Server Components by Default

Components in the App Router are React Server Components unless marked with "use client". That means you can fetch data directly in a page without useEffect: 

// app/projects/page.tsx — Server Component
export default async function ProjectsPage() {
  const projects = await fetchProjects();
  return <ProjectList items={projects} />;
}

Less JavaScript shipped to the browser, faster first paint, simpler data flow.

When to Use Client Components

Reach for "use client" when you need:

  • Event handlers (onClick, form interactivity)
  • Browser APIs (window, localStorage)
  • React hooks like useState and useEffect

Keep client boundaries small — wrap interactive islands, not entire pages, when possible.

Loading and Error UI

loading.tsx automatically wraps a route in Suspense. error.tsx catches runtime errors in that segment and shows a recovery UI. Both are conventions that replace boilerplate you'd otherwise write by hand.

Migration Tip

You don't have to migrate everything at once. Many teams run App Router for new features while legacy routes live in pages/. Next.js supports both simultaneously during transition.

Wrapping Up

The App Router rewards a server-first mindset: colocated routes, nested layouts, and selective client components. Start your next project with create-next-app, explore one dynamic route, and build from there — the patterns scale cleanly to production apps.
